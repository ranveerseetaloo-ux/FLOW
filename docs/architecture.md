# PipeCore architecture

PipeCore mirrors Allot's two-plane design: a **data plane** in the packet path
and a **control plane** for management and reporting.

## Data plane

A transparent Layer-2 bridge inserted between the international transport/upstream
and the provider-edge router. Because it is invisible at L3, it can be dropped
into the core with minimal reconfiguration. Every packet crosses the bridge and
is matched to its pipe by public IP / network group (u32 filter) or by DPI verdict
(fwmark `fw` filter).

Components:

- **Bridge / fast path** — XDP/eBPF (via LibreQoS). Line-rate steering before the
  kernel network stack.
- **Shaper** — `tc` HTB hierarchy with a **CAKE** leaf qdisc per class. HTB gives
  the rate (guarantee) + ceil (borrowing) semantics that implement every pipe
  type; CAKE removes bufferbloat, a concrete QoE differentiator. Generated by
  `shaper/tc_compiler.py`.
- **DPI** — nDPI resolves protocol/application per flow. First packets inspected
  in userspace; verdict cached as an fwmark in an eBPF flow map so the rest of the
  flow is shaped in-kernel. Interface in `shaper/dpi/classifier.py`.
- **Flow accounting** — per-flow counters exported to ClickHouse
  (`shaper/flow_exporter.py`).
- **Fail-safe** — hardware fail-to-wire bypass NIC + optional active/standby HA.
  Non-negotiable for an inline core device; the software applier also defaults to
  dry-run.

### Pipe types → tc mapping

| Pipe | HTB/CAKE realization |
|------|----------------------|
| Dedicated (100%) | class `rate == ceil` (no borrowing), CAKE leaf |
| Contended 1:N | parent `rate = Σplans/N`, `ceil = Σplans`; per-sub child `ceil = plan` |
| Time-based | scheduler recompiles + reapplies at each window boundary |
| Protocol | class matched by DPI fwmark (`fw` filter) |
| Application | class matched by DPI fwmark (nDPI L7 label) |

## Control plane

FastAPI service over PostgreSQL (config/inventory) and ClickHouse (flows).

- **Inventory** — customers, IP groups (public IP / CIDR), pipes, assignments.
- **Policy compiler** — `core/pipe_builder.py` reads the DB, builds the data-plane
  `InterfacePlan`, and compiles it; `/api/policies/apply` pushes to node agents.
- **Reporting** — `/api/reports/top` and `/download` query ClickHouse by
  application / protocol / pipe / IP / customer, with CSV export (PDF/XLSX next).
- **Auth** — JWT + role ranks (viewer < operator < admin); RADIUS/OIDC slot in
  behind the same router.
- **Dashboard** — single-file UI (`ui/index.html`) or Grafana
  (`reporting/grafana/dashboard.json`).

## Deployment

Package as an OVA/qcow2 appliance (KVM/ESXi). XDP runs in VMs via virtio; for a
true 10 Gbps with DPI use bare-metal or SR-IOV/passthrough NICs. Control plane and
data-plane node agent can co-locate on one box for a small ISP, or split (one
control plane managing many nodes) as you scale — the API is multi-node from day
one.
